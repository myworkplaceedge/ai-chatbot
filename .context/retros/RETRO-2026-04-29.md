## TL;DR

**The week was unusually productive but exposed structural risk.** 43 commits, 16 PRs merged, 5,300 net LOC, 34% test ratio, 0 prior incidents. The codebase ships features fast and tests them well.

But: the API has **zero authentication**, the UI has **stored XSS via LLM output**, and the new migration pipeline has **non-atomic application**. Together those compose a real exploit chain. There is **no CI/CD**, so 79 test files don't run on PR. Documentation drifted by 5 features in a single afternoon.

The fixes are bounded: ~50 minutes of CC time produces a single PR that closes critical security gaps, ~10 minutes closes doc drift, ~30 minutes adds CI. Net: **one PR + one CI commit takes the project from "demo-ready" to "production-defensible."**

## Structural Risks

### 1. The 18:00 batch-merge ritual is fragile

16 PRs landed in a single 90-minute window on 4/26. If any one of them broke main mid-batch, every later merge inherited a poisoned base. Today the team is small (2 people) and this works because there's no concurrent activity. As contributors grow, this becomes a real integration-risk multiplier.

**Mitigation:** spread merges across the week, OR stage them on a release branch and run the full sequence in isolation before merging to main. Either approach gates the integration risk.

### 2. ChatPage.tsx and gemini.ts are doing a lot

`src/pages/ChatPage.tsx` and `server/src/lib/gemini.ts` are the two most-changed files this week (7 changes each). ChatPage already absorbed a 778-LOC refactor on 4/23, then was modified 6 more times. Both files are accumulating responsibilities (chat UI + role-play state + handout suggestions + vocab download UI in ChatPage; multiple system-prompt builders + model wiring in gemini.ts).

**Mitigation:** before the next feature lands on either file, extract. Concrete trigger: if `wc -l` exceeds 500, split. Easier to extract before the next 5 features land than after.

### 3. No CI/CD — 79 test files don't run automatically

The repo has zero `.github/workflows/`. PRs aren't gated on tests passing, build succeeding, or anything else. A regression that breaks tests would land silently if no one runs `npm test` locally before merging.

**Mitigation:** add a single GitHub Actions workflow that runs `cd server && npm install && npm test`, plus `npm install && npm run build` from root, on every PR. This is ~30 LOC and ~30 minutes CC. Worth doing before the next contributor joins.

### 4. Fix-prefix is misleading

48% of commits use the `Fix #N` prefix, but most are features (e.g., "Fix #40: export lesson vocabulary as PDF" is a new feature). Real bug fixes are rare. This means `git log --grep="Fix"` mis-counts defect work.

**Mitigation:** adopt conventional commit prefixes (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`). Future retros can then accurately separate feature velocity from defect rate. Optional, but improves signal.
